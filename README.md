# Station Mini Root 0.3.12

[English](README.en.md) · [Скачать Windows / Linux](https://github.com/hertebeznat-cell/alice-station-1-mini-root/releases/tag/v0.3.12) · [Как работает root](docs/METHOD.md) · [Проверки](docs/VALIDATION.md)

Программа для получения **ADB root на Яндекс Станции Мини первого поколения — YNDX-0004, Amlogic A113X**. Интерфейс на русском и английском. Windows x64 и Linux x86_64; в Windows сборка образа выполняется через WSL.

## Как пользоваться

**В готовом Windows EXE уже встроены libusb и WinUSB-помощник. Собирать или скачивать их вручную не нужно.** Если версия 0.3.8 сообщает «Не найден libusb», закройте её, скачайте 0.3.12 и повторите установку зависимостей. Существующие WSL, ADB, рабочая папка и бэкапы сохраняются.

1. Скачайте архив своей системы из Releases и распакуйте его. Windows: запустите `StationMiniRoot.exe`. Linux: `chmod +x StationMiniRoot && ./StationMiniRoot`.
2. Нажмите **«Установить все зависимости»**. Программа найдёт или скачает ADB, выберет совместимый установленный WSL-дистрибутив, при необходимости установит официальный Debian и сборщик. В Linux подготовит инструменты/udev. Запросы Windows UAC и доверия драйверу подтверждаются в системных окнах.
3. Подключите именно Мини 1 USB-кабелем с передачей данных, когда программа попросит. В подтверждённом владельцем способе кнопки зажимать не нужно: программа ловит загрузчик и удерживает его USB-опросом («якорь»). Дождитесь успешной проверки первого этапа — без неё root и восстановление недоступны.
4. Нажмите **«Установить root»** и подтвердите модель. Программа сохранит полный исходный system, соберёт из него изменённый образ, запишет его, выполнит полное обратное чтение и проверку SHA-256, затем перезагрузит колонку и проверит `uid=0` через ADB.
5. После подтверждения root автоматически установятся **Homebrew 0.5.3** и его автозапуск. Менеджер открывается по IP колонки на порту `8088`, без входа и токена. Он проверяет собственные обновления GitHub каждые 5 часов. AirPlay и другие плагины устанавливаются отдельно через магазин.

Во время записи и обратного чтения сохраняйте питание и USB-соединение. Не используйте программу для других моделей станции. Готовая Linux-сборка сделана на Ubuntu 24.04 / glibc 2.39; для более старой системы соберите приложение из исходников на целевой системе.

## Если ранее установлен noupdate

Версия 0.3.12 распознаёт подтверждённый вариант прежнего патча `noupdate`: задача `updatesd` уже удалена, а `device_ota_update.sh` содержит точную известную заглушку. В этом случае сохраняются остальные задачи запуска и дополнительно блокируются известные OTA-входы. Произвольное отсутствие `updatesd` по-прежнему останавливает сборку. Если предыдущий запуск остановился с этой ошибкой до записи, закройте старый EXE, запустите 0.3.12 и повторите установку root; рабочую папку, ключи, WSL и бэкап сохраняйте.

## Прошивки с updater_switcher

Версия 0.3.12 поддерживает подтверждённый вариант Mini 1, где `updater_switcher` выбирает старый `updatesd` или новый updater. Проверяются точные пути, аргументы, отдельная задача `maind --platformd` и SHA-256 исследованного переключателя. Отключается только задача обновлений; `platformd`, `mediad` и другие службы сохраняются. Известные OTA-входы дополнительно блокируются, а неизвестные варианты по-прежнему останавливают сборку до записи.

Если предыдущая версия остановилась с «Не найден updatesd» до прошивки: закройте её, распакуйте 0.3.12 и повторите «Установить root». Сохраните прежнюю рабочую папку, ADB-ключ, бэкапы и выбранный WSL. Восстанавливать бэкап или переустанавливать WSL для этой ошибки не нужно.

## Что меняется

```text
Зависимости → TPL / USB-якорь → бэкап system (80 МиБ)
→ патч ADB и распознанных OTA-путей → сборка UBI из своего бэкапа
→ запись system → полное обратное чтение → SHA-256
→ загрузка → проверка ADB root → установка Homebrew
```

Пути и рабочая папка определяются автоматически. Другие разделы, включая bootloader, boot, nv и пользовательские данные, программа не перепрошивает. Штатная Алиса и сторонние приложения не отключаются и не удаляются. Homebrew ставится после подтверждения root; повторная попытка его установки после сбоя не требует повторной прошивки.

Блокируются распознанные штатные OTA-механизмы Яндекса: задача `updatesd` и известные скрипты обновления. Неизвестная структура останавливает сборку до записи. Номер прошивки не является жёстким разрешительным списком, но это не гарантия поддержки любой будущей версии.

Метод использует доступный **TPL/U-Boot**, а не доказанную «незакрываемую дыру BootROM». Подробности и ограничения — в [описании метода](docs/METHOD.md).

## Бэкап и восстановление

Рабочая папка по умолчанию:

- Windows: `%LOCALAPPDATA%\StationMiniRoot\work`.
- Linux: `${XDG_DATA_HOME:-~/.local/share}/StationMiniRoot/work`.
- Существующая сессия из настроек/прежней папки `~/StationMiniRoot` подхватывается автоматически.

Сохраните эту папку: она содержит личный ключ ADB, исходный бэкап и `session.json`. **Не публикуйте её.** Кнопка «Восстановить бэкап» возвращает точный исходный system и его исходное поведение OTA. Если до запуска программы system уже был изменён, восстановится именно сохранённая модификация, а не произвольная заводская прошивка. Перед восстановлением сохраняется текущий system и проверяется полное обратное чтение. Homebrew хранится в `/data`; возврат system сам по себе не объявляется удалением его данных.

## Исходники и сборка

Windows:

```powershell
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python station_mini_root.py
```

Debian / Ubuntu:

```bash
bash scripts/setup-linux.sh
bash start-linux.sh
```

Сборка готового приложения на соответствующей ОС:

```bash
python -m pip install -r requirements.txt pyinstaller==6.16.0
python scripts/prepare-homebrew.py
python -m unittest discover -s tests -v
python scripts/build-app.py
```

`prepare-homebrew.py` получает закреплённый официальный ARM64 Homebrew 0.5.3 и проверяет размер/SHA-256. Его исходники входят в `alice-homebrew/`; источник — [отдельный проект Homebrew](https://github.com/hertebeznat-cell/alice-homebrew). При сборке из Go-исходников используйте `CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -ldflags="-s -w" -o dist/alice-homebrew-linux-arm64 ./cmd/alice-homebrew` в этой папке, с Go 1.26.5.

**Только для разработчиков, собирающих приложение из исходников:** для Windows сначала соберите нативный WinUSB-помощник: [инструкция и полные исходники](native/README.md). Microsoft WDK redistributables получаются отдельно по их условиям. Помощник устанавливает WinUSB только для нужных загрузочного/ADB-интерфейсов; родитель составного устройства и RNDIS не заменяются, проверка подписей Windows не отключается.

Офлайн-сборка образа из **своего** полного бэкапа:

```bash
adb keygen /path/to/private/adbkey
bash scripts/build_image.sh /path/to/system-backup.bin /path/to/private/adbkey.pub /path/to/output.ubi
```

## Обновить Homebrew на уже рутированной колонке

Подключите колонку в обычном режиме ADB к прежнему ПК и нажмите «Обновить только Homebrew (ADB root)». Прошивать system заново не нужно. Требуется сохранённый авторизованный ADB-ключ в прежней рабочей папке. Этот способ также исправляет невозможность самообновления старого Homebrew из-за отсутствующего CA-хранилища; в комплекте 0.5.2 с встроенными сертификатами.
