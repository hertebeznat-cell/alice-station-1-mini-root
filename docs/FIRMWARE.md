# Поддерживаемые прошивки Мини 1

Root требует отключить автообновление прошивки Яндекса: обновление записывает заводской system поверх изменённого, и root пропадает. Программа отключает обновления только если **узнаёт**, как они устроены в вашей прошивке. Незнакомое устройство останавливает сборку образа **до записи** — колонка остаётся как была, а рядом с образом сохраняется `*.diagnostics.json` (версии и хеши файлов, без ключей и данных аккаунта).

Распознаются три варианта (`station_root/image_builder.py`):

| Вариант | Признаки | Что делается |
| --- | --- | --- |
| `stock-updatesd` | в `launch.json` есть задача `updatesd` | задача удаляется |
| `stock-updater-switcher-v1` | задача `updater_switcher` с точными путями и аргументами, рядом `maind --platformd`, а сам бинарник есть в белом списке | удаляется только задача обновлений; `platformd`, `mediad` и другие службы остаются |
| `noupdate-v1` | ранее установленный патч noupdate: `updatesd` уже нет, `device_ota_update.sh` — известная заглушка | патч сохраняется и дополняется |

Во всех вариантах известные точки входа OTA (`device_ota_update.sh`, `a01localupdate`) заменяются заглушкой.

## Белый список

`station_root/data/known-firmware.json` — хеши бинарников `updater_switcher`, проверенных на настоящих колонках, и точный текст заглушки noupdate. У каждой записи есть пояснение, откуда она взялась. Бинарник с другим хешем не принимается, даже если имя и путь совпадают: так программа не «угадывает» поведение незнакомого обновлятора.

Добавлять запись можно только после проверки бинарника на устройстве. Код при этом менять не нужно.

Номер версии прошивки сам по себе не является разрешением: решают структура `launch.json` и хеши файлов.
