# Проверки 0.3.12

Добавлены регрессионные сценарии подтверждённого updater_switcher и отказа без записи при неизвестном бинарнике, неверных аргументах, отсутствии platformd, символьной ссылке и дополнительной задаче updater. Сохраняются все поля остальных задач.

Полный образ из присланного бэкапа проверяется только офлайн с отдельным тестовым ADB-ключом: сравниваются содержимое, типы файлов, UID/GID, права и ссылки всех неизменяемых записей. Бэкап, тестовый образ и ключи остаются приватными. Записи на физическую колонку не выполнялось. Готовые Windows/Linux приложения проверяются на встроенную libusb и целостность Homebrew 0.5.3.

# Проверки 0.3.10

Результат: Windows — 73 теста, один платформенный пропуск; Linux — все 73 теста. Полный образ из бэкапа с прежним noupdate собран и сравнен офлайн: 1062 исходные записи, 1064 результирующие, у 1056 записей вне намеренно изменяемого списка совпали содержимое, mode, UID/GID и число ссылок. Проверка учитывает оба штатных расположения исходного adbd: adbd и adbd_backup. Windows/Linux-приложения проверили SHA-256 встроенной libusb и загрузку USB runtime из самого готового файла. Включён официальный Homebrew 0.5.1 по закреплённому SHA-256. На устройство тестовый образ не записывался.

Для исправления noupdate добавлены синтетические регрессионные сценарии: известный старый блокировщик, неизменность остальных служб, отказ при дополнительных командах/другом updater и неизвестном launch.json. Полный образ из предоставленного владельцем бэкапа проверяется только офлайн, с новым тестовым ADB-ключом; бэкап и результат остаются приватными. На физическую колонку исправление не устанавливалось. # Проверки сборки 0.3.9

Исходники и бинарные пакеты публикуются без повторной перепрошивки уже рутированной колонки.

- Метод получения root подтверждён владельцем на одной Mini 1; наличие ADB uid=0 подтверждалось отдельно. Полный цикл новой сборки на дополнительной нерутированной колонке не повторялся при публикации.
- Unit-тесты проверяют порядок бэкап → сборка → запись → обратное чтение → reboot → root, ошибки USB/сборщика, сохранение цели восстановления и распознавание известных вариантов activate_adb.sh.
- Проверяется выбор существующего совместимого WSL-дистрибутива, отсутствие обхода посторонних систем после успеха, различение сбоя запуска и отсутствия пакетов, однократный ремонт USB-драйвера и блокировка root/restore до готовности.
- Офлайн проверялась сборка из полного бэкапа с новым тестовым ключом: сохранение содержимого, прав, UID/GID, симлинков/числа ссылок для неизменённых элементов rootfs. Готовые образы и тестовые ключи не публикуются.
- Интеграция root → Homebrew проверялась на уже рутированной Mini 1 без повторной записи NAND. Отсутствует отключение штатной Алисы или удаление других приложений.
- Автообновление менеджера Homebrew с GitHub 0.4.0 → 0.4.1 действительно прошло на Mini 1: совпал SHA-256 официального ARM64 asset, сохранились плагины/конфиги и рабочий PID автозапуска.
- В сборку root включён закреплённый официальный Homebrew 0.4.1. Проверяются PE/ELF архитектуры, версия приложения, манифест Windows-помощника, точный SHA-256 Homebrew в PyInstaller-архиве и отсутствие личных ключей/пакетов плагинов.

В 0.3.8 проверка состава пакета не выявила отсутствующую libusb в Windows EXE. В 0.3.9 добавлены обязательные проверки: загрузка библиотеки в среде сборки, наличие и точный SHA-256 libusb в готовом PyInstaller-архиве, затем `--check-usb` именно готового приложения. Самопроверка не перечисляет и не открывает USB-устройства.

Windows и Linux unit-тесты выполняются перед выпуском и в CI. Аппаратные проверки на одной колонке и тесты с подменёнными USB/WSL не являются гарантией совместимости с любой ревизией, прошивкой или конфигурацией драйверов. Подробности метода — METHOD.md.

CI на Windows/Linux отдельно загружает именно libusb из пакета и вызывает её API версии. В Windows дополнительно создаётся реальный USB-контекст. На Linux cloud runner нет работоспособного USB host, поэтому полный контекст там не проверяется; `scripts/build-app.py` проверил полный backend в готовом Linux-бинарнике в WSL Ubuntu 24.04 и в Windows EXE. Аппаратная перепрошивка для этого исправления не выполнялась.
