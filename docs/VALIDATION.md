# Проверки первой публичной сборки 0.3.8

Исходники и бинарные пакеты публикуются без повторной перепрошивки уже рутированной колонки.

- Метод получения root подтверждён владельцем на одной Mini 1; наличие ADB uid=0 подтверждалось отдельно. Полный цикл новой сборки на дополнительной нерутированной колонке не повторялся при публикации.
- Unit-тесты проверяют порядок бэкап → сборка → запись → обратное чтение → reboot → root, ошибки USB/сборщика, сохранение цели восстановления и распознавание известных вариантов activate_adb.sh.
- Проверяется выбор существующего совместимого WSL-дистрибутива, отсутствие обхода посторонних систем после успеха, различение сбоя запуска и отсутствия пакетов, однократный ремонт USB-драйвера и блокировка root/restore до готовности.
- Офлайн проверялась сборка из полного бэкапа с новым тестовым ключом: сохранение содержимого, прав, UID/GID, симлинков/числа ссылок для неизменённых элементов rootfs. Готовые образы и тестовые ключи не публикуются.
- Интеграция root → Homebrew проверялась на уже рутированной Mini 1 без повторной записи NAND. Отсутствует отключение штатной Алисы или удаление других приложений.
- Автообновление менеджера Homebrew с GitHub 0.4.0 → 0.4.1 действительно прошло на Mini 1: совпал SHA-256 официального ARM64 asset, сохранились плагины/конфиги и рабочий PID автозапуска.
- В сборку root включён закреплённый официальный Homebrew 0.4.1. Проверяются PE/ELF архитектуры, версия приложения, манифест Windows-помощника, точный SHA-256 Homebrew в PyInstaller-архиве и отсутствие личных ключей/пакетов плагинов.

Windows и Linux unit-тесты выполняются перед выпуском и в CI. Аппаратные проверки на одной колонке и тесты с подменёнными USB/WSL не являются гарантией совместимости с любой ревизией, прошивкой или конфигурацией драйверов. Подробности метода — METHOD.md.
