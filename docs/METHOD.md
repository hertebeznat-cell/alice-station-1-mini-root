# Метод получения ADB root и совместимость

## Подтверждённый путь

Цель — Mini 1 YNDX-0004, Amlogic A113X, NAND 256 МиБ, system 80 МиБ. При подключении загрузчик отвечает на `upload store system normal 0x5000000` и IDENTIFY `0007001000000000`. Это доступный **TPL**, а не доказательство выполнения кода в IPL/BootROM. Для исследованной системы версия — `1.356.4.5.4321993220.20260629`; конкретный номер не является разрешительным списком.

Владелец подтвердил подключение без кнопок. Программа ловит `1B8E:C003`, выполняет `low_power` и опрашивает IDENTIFY каждые 0,5 с. USB-операции последовательны; во время сборки опрос продолжается, а вывод процесса читается отдельным потоком. В исследованной штатной системе adbd уже способен работать от root; изменяются условия его запуска и авторизация, а не публикуется чужой готовый firmware.

## Можно ли подтвердить незапатчиваемую дыру?

Нет: локальные файлы доказывают доступ к штатному TPL/U-Boot и изменение system, но не эксплуатацию ошибки масочного ROM A113X. Масочный ROM не заменяется обычной записью system; сохранность всей цепочки доступа после любого обновления этим не доказана.

Первичные источники:

- [Dumping the Amlogic A113X Bootrom](https://haxx.in/posts/dumping-the-amlogic-a113x-bootrom/): описаны ошибки BL31/secure monitor, зависимость USB recovery от eFUSE, а известная автору ошибка amlogic-usbdl, по предварительному анализу, не обнаружена в A113X.
- [frederic/amlogic-usbdl](https://github.com/frederic/amlogic-usbdl): поддерживаемые цели — s905d2/s905d3, не A113X.
- [U-Boot Amlogic boot flow](https://android.googlesource.com/platform/external/u-boot/+/master/doc/board/amlogic/boot-flow.rst): ROM-загрузка и последующие стадии семейства A113X.

Утверждение «Яндекс никогда не закроет» не подтверждено. Эта программа не использует указанные сторонние эксплойты и не заявляет работу на заблокированном TPL.

## Разные версии

В 0.2 исходный SHA-256 больше не является разрешением на root. Вход — полный бэкап подключённой колонки. Проверяются один dynamic rootfs id 0, PEB 131072, LEB 126976, min I/O 2048, UBIFS v4/r5 и system 80 МиБ. Размер тома, max LEB count и image sequence берутся из UBI.

Восстанавливается штатный ARM/AArch64 adbd, устанавливается новый публичный ключ, отключается распознанная деактивация ADB, выбирается USB-ветка S89usbgadget. Неизвестные компоненты останавливают подготовку до записи. Другой бинарник adbd может сбрасывать привилегии: успех проверяется только `id` после загрузки.

## OTA

В локальном launch.json есть отдельная задача updatesd / --updatesd; device_ota_update.sh вызывает apply_packed_ota и reboot, также найден a01localupdate. Патч удаляет только задачу обновления и заменяет entry points скриптом exit 78. Symlink заменяется как отдельная запись, чтобы не переписать общий multicall-бинарник. Остальные задачи и maind сохраняются. Маркер: /etc/station-mini-root.json.

После загрузки проверяются маркер и отсутствие --updatesd в процессах. При неизвестной схеме сборка с блокировкой OTA останавливается. Обнаруженные пути блокируются; обещание блокировки любых будущих OTA/recovery не даётся.

## Запись и возврат

Распаковка с -k в Linux-ФС и mkfs выполняются в одном fakeroot-сеансе. ubi-reader не воспроизводит журнал UBIFS: используется зафиксированное дерево, полный исходный дамп отдельно сохраняется для возврата.

UBIFS упаковывается в полный UBI, дополняется FF до 80 МиБ и передаётся как system normal. Инициализация только disk_initial 0. Каждый блок 64 КиБ требует OK!!, затем download get_status, полный read-back и SHA-256. Bootloader, tpl, boot, nv, bkupgrade, recovery не записываются.

session.json хранит исходник, хэши и состояние операции. Возврат восстанавливает исходный system с его OTA-настройками. Неудачная повторная подготовка сохраняет прежний бэкап для возврата. Уже помеченный патчем этой программы исходник не принимается как чистый.

## WSL

Использованы [официальные команды Microsoft](https://learn.microsoft.com/windows/wsl/reference): --install --no-distribution, установка Debian с --no-launch --web-download и выбор дистрибутива/пользователя root. Программа не удаляет дистрибутивы, не меняет default и не перезагружает Windows. До готовности сборщика прошивка не начинается.
