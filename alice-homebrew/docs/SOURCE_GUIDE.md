# Как создать свой источник плагинов на GitHub

Источник — подписанный `catalog/v1.json` и файлы `.aliceplugin`. GitHub может хранить их бесплатно в публичном репозитории. Постоянно работающий сервер не нужен: модерация и подпись выполняются на вашем компьютере, а колонка скачивает опубликованные файлы.

## Наш официальный источник

Репозиторий: [hertebeznat-cell/alice-homebrew](https://github.com/hertebeznat-cell/alice-homebrew).

В менеджер встроены адрес и публичный ключ нашего каталога. Его источник уже добавлен по умолчанию. Официальность определяется известным адресом **и** закреплённым ключом подписи. Имя «Official», размещение на GitHub или поле в чужом JSON не дают официальную отметку.

Основной адрес работает прямо с GitHub:

```text
https://raw.githubusercontent.com/hertebeznat-cell/alice-homebrew/main/docs/catalog/v1.json
```

После включения GitHub Pages можно использовать и:

```text
https://hertebeznat-cell.github.io/alice-homebrew/catalog/v1.json
```

Остальные каталоги показываются как сторонние. Это не оценка качества: их проверяет и подписывает другой владелец. Пользователь отдельно подтверждает, что доверяет такому источнику.

## 1. Запустите локальную панель модератора

Скачайте готовый Alice Homebrew и распакуйте архив. Откройте терминал в этой папке.

Windows:

```powershell
.\bin\alice-homebrew-windows-amd64.exe store --data .\moderator-data
```

Linux x86_64:

```bash
./bin/alice-homebrew-linux-amd64 store --data ./moderator-data
```

Откройте `http://127.0.0.1:8089`. Это панель владельца источника на компьютере, а не менеджер пользователя на колонке. Код для этой панели находится в `moderator-data/admin-token.txt`. Менеджер на колонке работает без кода входа.

При первом запуске создаётся закрытый ключ `moderator-data/catalog-signing.key`. Сделайте отдельную резервную копию **всей папки moderator-data**. При потере ключа продолжить подпись прежним ключом нельзя. Эта папка не должна попадать в публичный репозиторий, экспорт или GitHub Actions. В `.gitignore` проекта она уже исключена; при работе в другом репозитории добавьте исключение сами.

Не запускайте две панели на одной папке данных одновременно. Для другого независимого источника используйте отдельную папку.

## 2. Добавьте пакет и проверьте его

Пакет создаётся по [гайду разработчика](PLUGIN_GUIDE.md). В панели нажмите **«Отправить .aliceplugin»** и выберите файл. В очереди появятся версия, права и SHA-256.

Изучите исходники соответствующего commit и проверьте поведение на компьютере и совместимой колонке. Проверяйте именно тот файл, чей SHA-256 указан в очереди. Для антивирусной проверки можно передать путь к установленному ClamAV:

```bash
./bin/alice-homebrew-linux-amd64 store --data ./moderator-data --scanner /usr/bin/clamscan
```

Если сканер не настроен, панель прямо это показывает. Положительный результат технической проверки не заменяет просмотр исходников и поведения. При угрозе или ошибке сканера одобрение блокируется.

После проверки отметьте **«Проверка исходников и работы выполнена для этого SHA-256»** и нажмите **«Одобрить»**. В каталоге появится только эта одобренная версия. Новая версия подаётся и проверяется отдельно.

## 3. Создайте репозиторий и экспорт

Создайте на GitHub публичный репозиторий, например `yourname/my-alice-source`. Для собственного исходного кода выберите подходящую лицензию; лицензии плагинов зависят от их авторов.

В панели откройте **«Публикация»**, укажите:

```text
https://github.com/yourname/my-alice-source
```

Нажмите **«Скачать готовый сайт»**. Распакуйте экспорт. В нём:

```text
docs/
  index.html
  store.js
  style.css
  site.json
  public-key.txt
  .nojekyll
  catalog/v1.json
  packages/<SHA-256>.aliceplugin
.github/
  ISSUE_TEMPLATE/plugin.yml
README.md
```

Загрузите содержимое экспорта в ветку `main`. Не создавайте дополнительную внешнюю папку вокруг `docs`: пути в каталоге рассчитаны на указанную структуру. Если репозиторий уже содержит приложение/документацию, объедините файлы, не заменяя свой README вслепую.

Закрытого ключа и кода модератора в экспорте нет. Подписанный JSON вручную не редактируйте: изменение полезной нагрузки делает подпись недействительной.

## 4. Подключите источник без сайта

После публикации файлов источник уже можно добавить в менеджер:

1. Откройте на колонке **«Настройки → Добавить источник»**.
2. Вставьте `https://github.com/yourname/my-alice-source`.
3. Нажмите **«Проверить источник»**.
4. Проверьте адрес, публичный ключ и отметку **«Сторонний источник»**.
5. Подтвердите доверие автору и добавление.

Менеджер преобразует ссылку на репозиторий в адрес `main/docs/catalog/v1.json`, прочитает публичный ключ из конверта и проверит подпись. При желании заранее укажите ключ, полученный от автора отдельно: тогда файл должен соответствовать именно ему. Автоматическое получение чужого ключа подтверждает согласованность подписи, а не независимую проверку личности владельца.

Можно вместо репозитория указать прямой адрес JSON. Для ветки с другим именем используйте её прямой raw URL.

## 5. При желании включите GitHub Pages

В репозитории откройте **Settings → Pages → Build and deployment → Deploy from a branch → main → /docs → Save**. Дождитесь успешной публикации.

Для указанного примера сайт будет по адресу:

```text
https://yourname.github.io/my-alice-source/
```

Его можно вставить в **«Добавить источник»** без ручного указания JSON. Менеджер добавит `catalog/v1.json`. Сам статический сайт показывает каталог, подпись, публичный ключ и ссылки на пакеты.

GitHub Pages не запускает сервер модерации. Заявки авторов поступают через Issues; шаблон уже включён. Перенос пакета из заявки в локальную очередь пока выполняется вручную. [Документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## 6. Обновления и отзыв версии

После нового одобрения, отказа от опубликованной версии или отзыва снова экспортируйте каталог и опубликуйте обновлённые файлы. Источник проверяется при запуске менеджера и кнопками обновления. Постоянного фонового опроса в текущей версии нет.

Если обнаружена проблема в опубликованной версии, нажмите **«Отозвать версию»**, затем опубликуйте свежий экспорт. После обновления соответствующего источника менеджер остановит отозванную версию. Отзыв из одного источника не даёт ему права отключать плагины другого источника. Известные отзывы и максимальная ревизия сохраняются; удаление и повторное добавление того же источника не сбрасывает защиту от отката каталога.

Экспорт действует год. Даже если новых плагинов нет, до истечения срока сделайте новый экспорт. Установленные плагины работают без интернета; для просмотра и установки новых версий нужен действительный каталог.

## 7. Источник в локальной сети

Временно раздавайте **только публичную папку docs**, а не каталог с данными модератора:

```bash
python3 -m http.server 8000 --bind 0.0.0.0 --directory docs
```

На колонке добавьте `http://IP-КОМПЬЮТЕРА:8000/`. Для локального IP допускается HTTP; для обычного интернет-адреса используйте HTTPS. Подпись и закреплённый ключ всё равно проверяются. Укажите IP компьютера, а не `localhost`. После проверки остановите временный сервер.

## Частые ошибки

- **404:** проверьте ветку `main`, папку `docs` и путь `catalog/v1.json`; для Pages проверьте завершение публикации.
- **Подпись не совпадает:** опубликован не тот каталог, указан другой ключ или JSON изменён после экспорта. Верните исходный экспорт; не исправляйте подпись вручную.
- **Каталог старее сохранённой ревизии:** загрузите свежий экспорт из прежней папки модератора. Не создавайте новый пустой каталог под прежним адресом в попытке сбросить историю.
- **Источник неофициальный:** для собственного каталога это ожидаемо. Официальная отметка принадлежит только встроенному источнику проекта.
- **Новая версия не появилась:** проверьте одобрение конкретной версии и повторите экспорт, публикацию и обновление источника в менеджере.
- **Закончился диск:** откройте настройки колонки, сравните размеры плагинов и сохранённых версий, скачайте нужные конфиги и удалите выбранные плагины. Менеджер не удаляет другие файлы колонки самостоятельно.


## Каталог SDK 2

Homebrew 0.3 экспортирует `catalog/v1.json` для WASM SDK 1 и `catalog/v2.json` для WASM и нативных SDK 2 плагинов. Новые менеджеры автоматически выбирают v2 по ссылке на сайт/репозиторий, со старым источником возможен возврат к v1. Оба каталога используют один ключ подписи. Для прямой ссылки на полный каталог выбирайте v2.
