> Для микрофона, динамика, датчика, кнопок, сети и других аппаратных интерфейсов используйте [нативный SDK 2](NATIVE_SDK.md). Ниже описан изолированный WASM SDK 1.

# Как сделать свой плагин Alice Homebrew

Этот гайд рассчитан на первую рабочую версию плагина: берём пример, меняем поведение и настройки, собираем `.aliceplugin`, проверяем на компьютере и устанавливаем на колонку.

Плагин — модуль WebAssembly с описанием и схемой настроек. Он работает внутри Homebrew. В SDK 1 доступны кольцо подсветки и журнал; произвольные shell-команды, Python, доступ к файлам и сеть модулю не предоставляются. Одного переименования обычной программы в `.aliceplugin` недостаточно.

## 1. Подготовьте инструменты

Скачайте исходники этого репозитория. Для сборки самого менеджера нужен Go 1.26 или новее. Для C-примера нужны `clang` и `wasm-ld` из LLVM. На Windows удобнее собирать C-пример в Linux/WSL; запускать готовый пакет можно в Windows-версии Homebrew.

В Debian/Ubuntu инструменты для примера устанавливаются так:

```bash
sudo apt update
sudo apt install clang lld
```

Это инструменты компьютера разработчика. На колонку компилятор не устанавливается.

Если готовый Homebrew уже скачан, команды `go run ./cmd/alice-homebrew ...` ниже можно заменить вызовом своего бинарника, например `./bin/alice-homebrew-linux-amd64 ...` или `./bin/alice-homebrew-windows-amd64.exe ...`.

## 2. Скопируйте Ring Studio

Начните с папки [examples/ring-studio](../examples/ring-studio). В ней:

```text
manifest.json   название, версия, разрешения и настройки
plugin.c        исходник примера
plugin.wasm     собранный модуль
README.md       инструкция пользователя
LICENSE         лицензия примера
```

Для первой пробы измените существующий пример на компьютере, а после знакомства со сборкой скопируйте его в отдельную папку своего проекта. В `manifest.json` задайте собственный `id`, автора, название и версию. Например, `yourname.soft-light`, а не `alice.ring-studio`: ID определяет, какой установленный плагин обновляется.

## 3. Опишите плагин и визуальный конфиг

Минимальный пример манифеста с настройками:

```json
{
  "format": 1,
  "id": "yourname.soft-light",
  "version": "1.0.0",
  "title": {"ru": "Мой свет", "en": "My light"},
  "description": {"ru": "Настраиваемая подсветка", "en": "Configurable light"},
  "author": "Your name",
  "api": 1,
  "permissions": ["led.ring"],
  "module_sha256": "",
  "config": [
    {
      "key": "color",
      "label": {"ru": "Цвет", "en": "Color"},
      "type": "color",
      "default": "#a5d178"
    },
    {
      "key": "brightness",
      "label": {"ru": "Яркость", "en": "Brightness"},
      "type": "range",
      "default": 30,
      "min": 0,
      "max": 100,
      "step": 1
    },
    {
      "key": "reverse",
      "label": {"ru": "Обратное направление", "en": "Reverse"},
      "type": "boolean",
      "default": false
    }
  ]
}
```

`module_sha256` заполняет пакетировщик. Поля `format` и `api` для этого SDK равны `1`.

Поддерживаемые поля конфигурации:

| Тип | Что появляется в панели | Дополнительные параметры |
| --- | --- | --- |
| `color` | Выбор цвета и ввод HEX | `default` в формате `#RRGGBB` |
| `range` | Ползунок и точный ввод числа | `min`, `max`, `step`, числовой `default` |
| `boolean` | Переключатель | `default`: `true` или `false` |
| `select` | Выпадающий список | `options`: массив `value` и `label` |
| `text` | Строка | `max_length` и строковый `default` |

Пример списка:

```json
{
  "key": "animation",
  "label": {"ru": "Эффект", "en": "Effect"},
  "type": "select",
  "default": "solid",
  "options": [
    {"value": "solid", "label": {"ru": "Постоянный", "en": "Solid"}},
    {"value": "breathe", "label": {"ru": "Дыхание", "en": "Breathe"}}
  ]
}
```

Менеджер сам рисует форму. Пользователь вводит значения и нажимает **«Сохранить настройки»**. Homebrew проверяет типы, диапазон и шаг, сохраняет конфигурацию на колонке и передаёт её модулю на следующих tick. После перезапуска значения остаются. Конфиг можно скачать кнопкой в карточке плагина.

Для совместимых обновлений сохраняйте прежние `key` и типы. Новый параметр должен иметь допустимое значение `default`. Если новое ограничение делает старое значение недопустимым, обновление остановится с ошибкой миграции вместо молчаливой потери настроек.

## 4. Напишите поведение

Начните с рабочего [plugin.c](../examples/ring-studio/plugin.c): там уже есть импорты SDK, чтение строк, цвета и анимации. Модуль экспортирует:

```c
void alice_tick(unsigned int milliseconds);
```

Память экспортируется под именем `memory`. Homebrew вызывает tick примерно десять раз в секунду. Не делайте внутри ожидание, бесконечный цикл или длинную работу: на один tick отведено 20 мс.

Импорты из пространства имён `alice`:

| Функция | Результат | Назначение |
| --- | --- | --- |
| `config_number(key_ptr, key_length)` | `f64` | Число; boolean передаётся как 0/1 |
| `config_string(key_ptr, key_length, out_ptr, capacity)` | `i32` | Копирует UTF-8 строку, возвращает длину |
| `led_write(pointer, 36)` | `i32` | Передаёт один кадр кольцу, нужен `led.ring` |
| `log(pointer, length)` | нет | Добавляет сообщение в журнал, нужен `log.write` |

У кольца 12 светодиодов, по три байта на каждый: **B, G, R**, всего 36 байт. Допускается один кадр за tick. Яркость обычно применяется в самом модуле: умножьте значения каналов на `brightness / 100`.

Ограничения v1: память WASM до 2 МиБ, сам модуль до 2 МиБ, архив и его распакованные данные до 4 МиБ. Журнал и число host-вызовов ограничены. Ошибка/таймаут отключает плагин. Одновременно кольцом управляет один плагин. Другие разрешения не станут доступны от добавления произвольного имени в манифест: для них нужна поддержка в самом SDK.

## 5. Соберите и проверьте

Из корня репозитория для исходного примера:

```bash
bash scripts/build-example.sh
go run ./cmd/alice-homebrew pack examples/ring-studio build/MyLight-1.0.0.aliceplugin
go run ./cmd/alice-homebrew check build/MyLight-1.0.0.aliceplugin
```

Для своего проекта поменяйте путь в команде `pack`. Скрипт `build-example.sh` показывает флаги компиляции freestanding WASM без WASI; используйте их для сборки своего C-файла.

Пакет — ZIP только с `manifest.json`, `plugin.wasm` и необязательными `README.md`/`LICENSE`. Исходный C-код публикуйте отдельно в репозитории. В архиве плагина не должно быть каталогов, ссылок, исполняемых Linux-файлов или произвольных дополнительных файлов.

`check` проверяет формат и возможность загрузки модуля. Он не доказывает полезность поведения или отсутствие всех ошибок: отдельно проверьте конфиг, работу и ограничения.

## 6. Проверьте сначала на компьютере

```bash
go run ./cmd/alice-homebrew station --listen 127.0.0.1:8088 --data station-data
```

Откройте `http://127.0.0.1:8088`. Вход не требуется. Нажмите **«Добавить пакет»**, выберите свой `.aliceplugin`, подтвердите права и доверие локальному пакету. После установки включите плагин. Изображение кольца показывает кадры настоящего модуля WASM.

Проверьте крайние значения, точный ввод чисел, все варианты списка, сохранение и повторное открытие конфига, перезапуск менеджера, выключение и ошибки. Учтите, что предпросмотр на компьютере не проверяет электрику и поведение реальных светодиодов.

## 7. Установите на колонку

На подготовленной Мини 1 откройте `http://IP-КОЛОНКИ:8088`. Пакет можно загрузить через браузер или дать ссылку кнопкой **«По ссылке»**. Скачивает его сама колонка.

Для файла на компьютере можно временно открыть папку с пакетом:

```bash
python3 -m http.server 8000 --bind 0.0.0.0 --directory build
```

В менеджере укажите `http://IP-КОМПЬЮТЕРА:8000/MyLight-1.0.0.aliceplugin`. Не пишите `localhost`: для службы на колонке это сама колонка. После передачи остановите временный сервер. SHA-256 можно указать дополнительно.

При нехватке места менеджер показывает доступное место и предлагает выбрать установленные плагины для удаления, начиная с самых больших. Удаление требует вашего выбора; настройки выбранных плагинов удаляются вместе с ними. Сначала скачайте нужные конфиги.

## 8. Выпустите обновление или предложите плагин

Для новой версии увеличьте `version`, соберите новый пакет и разместите его в GitHub Release своего проекта. Версии в источнике неизменяемы: нельзя заменить уже одобренный файл другим под тем же ID и номером версии.

Чтобы предложить плагин в наш каталог, откройте [заявку](https://github.com/hertebeznat-cell/alice-homebrew/issues/new?template=plugin.yml). Приложите ссылку на пакет, SHA-256, ссылку на исходники и точный commit, требуемые разрешения и результаты тестов. Заявка не означает автоматического одобрения. Личные API-ключи, токены и настройки пользователя в пакет/репозиторий не включайте.

Для собственного каталога продолжайте с [гайдом по источникам](SOURCE_GUIDE.md).
