# Обновления самого менеджера

Начиная с Homebrew 0.4.0 служба на колонке автоматически проверяет стабильные релизы `hertebeznat-cell/alice-homebrew` на GitHub раз в **5 часов**. После первой установки первая проверка выполняется примерно через 15 секунд. Время следующей проверки сохраняется на диске: перезапуск не начинает очередной пятичасовой интервал заново.

В «Настройки» → «Обновления менеджера» видны установленная и найденная версии, время последней и следующей проверки, результат и ошибка. Там же можно выключить автоматическую установку или нажать «Проверить сейчас». Пароль/токен GitHub не требуется. Источники плагинов не могут изменить источник обновлений менеджера.

Обновляется только программа менеджера. Плагины, их настройки, ADB root, прошивка и штатная Алиса не обновляются и не отключаются этим механизмом. При замене менеджер ненадолго становится недоступен; включённые плагины останавливаются и запускаются снова.

## Как устанавливается версия

1. Проверяется публичный GitHub Releases API `releases/latest` фиксированного репозитория.
2. Принимается только более новая стабильная версия вида `vMAJOR.MINOR.PATCH`. Черновики, prerelease и понижение версии не устанавливаются.
3. Загружается отдельный файл `alice-homebrew-linux-arm64` (для Linux AMD64 — соответствующий AMD64 файл) из этого релиза. Проверяются заявленный размер, SHA-256 из метаданных GitHub, архитектура ELF и команда `version`.
4. Служба корректно останавливается. Сохраняются предыдущий исполняемый файл и снимок `state.json`, содержащий настройки/состояние плагинов. Файлы плагинов при обновлении менеджера не заменяются.
5. Исполняемый файл заменяется в той же файловой системе. Временный helper запускает новую службу и проверяет её версию и готовность по loopback HTTP.
6. Если запуск/проверка готовности не удались, возвращаются предыдущий менеджер и состояние. Такая версия больше не ставится автоматически: нужно выпустить более новую либо вручную повторить проверку.

Журнал транзакции позволяет init-скрипту восстановить прерванную замену после перезагрузки. Предыдущий исполняемый файл хранится рядом как `alice-homebrew.previous`; используется одна такая копия. Дополнительный запас места — новый бинарный файл, снимок состояния и резерв 8 МиБ. При нехватке диска, ошибке сети или неверной контрольной сумме работающая программа остаётся на месте, ошибка показывается в настройках.

SHA-256 проверяется по метаданным GitHub через HTTPS. Источник доверия здесь — официальный репозиторий и GitHub; это не отдельная подпись закрытым ключом каталога плагинов. Скачанные файлы ограничены 32 МиБ, перенаправления допускаются только на используемые GitHub HTTPS-хосты.

## Автозапуск и ручной запуск

Штатный установщик и `start-speaker.sh` включают `--managed`. Этот режим разрешает автоматическую замену и перезапуск службы. Скрипт следит за новым PID после обновления.

В Windows-предпросмотре и при обычном запуске `station` без `--managed` доступна ручная проверка наличия версии, но автоматическая замена не выполняется. Для полноценного автоматического обновления на колонке используйте установщик, который ставит службу и init hook.

API локального менеджера:

```text
GET  /api/updates
POST /api/updates/check       {}
POST /api/updates/settings    {"enabled": true}
```

## Как выпустить обновление

Измените `Version` в `internal/homebrew/version.go`, внесите изменения и обновите `RELEASE_NOTES.md`. После push в `main` GitHub Actions выполняет тесты, собирает три платформы и публикует релиз этой версии, если он ещё не существует. Отдельные бинарные файлы и SHA256SUMS входят в assets релиза вместе с ZIP.

Существующие релизы неизменяемы в нашем workflow. Для исправления уже опубликованной сборки повышайте версию. Один коммит в `main` без нового номера версии не является обновлением для установленных колонок.

Проверки перед первым выпуском: успешная замена отдельного Linux-процесса, готовность новой версии, сохранение включённого WASM-плагина/его конфига, отказ запуска новой версии с восстановлением старой, восстановление прерванной транзакции, неверный SHA-256, чужой репозиторий/архитектура, prerelease, откат версии и сохранение расписания. Полный цикл проверяется на локальном стенде; будущие релизы требуют собственной проверки совместимости.
